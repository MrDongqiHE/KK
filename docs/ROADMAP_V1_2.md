# AMR 管理系统 V1.2 实施规划

## 第一阶段（本次 PR）

- Supabase 邮箱注册、登录、会话恢复与退出。
- 项目真实数据读取、新建、编辑和删除。
- 项目成员级 RLS；删除仅允许管理员和项目经理。
- 地区 → 项目 → 工厂 → 产线 → 问题的数据基础模型。
- 未解决问题视图包含地区、项目、工厂、产线、机器人数量、等级、发现时间、状态和进度。

## 第二阶段：人员出差与调休

- 日历事件：正常上班、客户现场、出差、周末出差、调休、请假、远程支持。
- 自动余额：周末出差产生调休 + 管理员调整 - 已使用调休。
- 人工调整记录天数、原因、操作人和时间，不直接覆盖余额。
- 可配置周末折算规则和超期未调休提醒。

## 第三阶段：客户需求与 P001–P008

- P001 内部技术协议；P002 测试报告；P003 客户需求冻结；P004 项目维护；P005 现场日报；P006 问题与变更；P007 现场配置；P008 客户使用规范。
- 机器人型号、数量、业务流和客户需求等主数据只录入一次，由各文档引用。
- 需求保留客户原文、HIK理解、标准/定制、P0/P1/P2、确认状态、负责人、期限和变更记录。

## 第四阶段：完整产线健康管理

- 运行状态与健康状态分离。
- 绿色：无未关闭问题；浅橘色：1–3 个普通未关闭问题；红色：超过 3 个或存在严重影响生产的问题。
- 问题详情支持临时措施、根因、永久方案、负责人、期限、机器人编号和处理历史。
- 稳定运行天数从投产日或最后一个影响生产问题的解决时间计算。

## 上线前需要决定

1. 首位管理员的账号邮箱，由 Supabase SQL 明确授予 `admin`，禁止前端自助提权。
2. 项目删除是否继续永久删除，还是改为可恢复的软删除（推荐）。
3. 周末出差一天对应多少调休，以及半天和跨时区如何计算。
4. 客户账号是否可见问题根因、内部备注和人员日常。
